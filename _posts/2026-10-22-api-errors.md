## 问题

失败时有时返回 200 加一个 flag，有时返回 500 加一整页栈。调用方无法判断要不要重试。

## 结论

调用方的错误用 4xx，服务自己的错误用 5xx。4xx 里写清是参数、认证还是权限，调用方不该重试一个永远会错的请求。5xx 和超时才是可能重试的。响应里给稳定的机器可读代码，和一句给人看的话。内部异常写进日志，用同一个请求编号把两边串起来。

## 依据

不要用 HTTP 200 包住所有失败，否则监控和重试都失效。也不要把数据库报错原文返回，那既不稳定，也会泄露结构。列表可以空，空不是错误。

## 还不确定

各家对 409、422、429 的细分不完全一样。选定一套之后在自己的 API 里保持一致，比追一个万能表更重要。
