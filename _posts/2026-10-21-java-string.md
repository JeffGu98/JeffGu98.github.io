## 问题

想就地修改一个字符串，发现 API 都是返回新串。不确定这是语法习惯还是有实际后果。

## 结论

String 创建之后字符序列不能变。因此多个引用可以共用同一个实例，哈希可以算一次就存着，拿它当 HashMap 的键或当锁的一部分不会中途变掉。需要拼接很多段时，用 StringBuilder 在一个可变缓冲里改，最后再 toString。安全上，敏感信息放进 String 会一直留到回收，改不掉内容，这是不可变的代价。

## 依据

源码里 value 是 final 的数组，公开方法不改这个数组。从 Java 7 起，substring 会拷贝所需的字符，不再和原串共用整个数组。拼接用 + 在循环里会不断产生新对象，可以用 javap 看编译器是否改写成了 StringBuilder。

## 还不确定

字符串常量池和 intern 的驻留范围跟 JDK 版本有关。不要假设所有相同内容的字符串都是同一个对象。
